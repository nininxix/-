# 贴吧「我的回贴」分页接口分析指南

> 目标：绕过浏览器 UI，直接用 HTTP 请求翻页拿数据 + 删除，速度比 UI 自动化快一个数量级。
> 前置：你已经能正常用 `main.py` 连上登录的 Edge。

## 一、整体思路

浏览器做的每一件事，本质都是发 HTTP 请求。所以只要：

1. 抓出「回贴列表」的**分页请求**；
2. 用同一个 Cookie **复刻**这个请求；
3. 解析返回的 JSON，拿到每条回贴的 ID；
4. 再抓到「删除」的请求，同样复刻。

就能完全不点页面，直接跑接口。

## 二、第一步：抓包找到分页接口

1. 在登录好的 Edge 里按 `F12` 打开开发者工具。
2. 切到 **Network（网络）** 标签。
3. 过滤栏点 **Fetch/XHR**（只看接口，过滤掉图片 / css / js）。
4. 切到「回贴」tab，然后**向下滚动**，触发加载更多。
5. 观察右侧新冒出来的请求，找到那个**返回 JSON、且里面含你的回贴内容**的请求。

   - 关键词提示：URL 里常见 `reply`、`thread`、`page`、`pn`、`pb`、`commit` 等。
   - 点开请求 → **Response / 响应** 标签，能看到你回贴的文字，就是它。

## 三、第二步：分析请求

点开这个请求，看三样东西：

### 1. Query String Parameters（查询参数）

常见字段：

| 参数 | 含义 |
|------|------|
| `pn` | 页码，从 1 开始，递增就是翻页 |
| `rn` | 每页条数（比如 20、30） |
| `uid` / `user_id` | 你的用户 ID |
| `ie` | 编码，一般是 `utf-8` |

**验证翻页**：把 `pn` 从 1 改成 2、3，看返回内容是否变化 —— 变了就说明这是翻页参数。

### 2. Request Headers（请求头）

关键的几个：

- `Cookie`：**最重要**，你的登录凭证，必须原样带上。
- `User-Agent`：浏览器标识，带上更安全。
- `Referer`：来源页面，带上更安全。

### 3. 复制请求

右键请求 → **Copy → Copy as cURL (bash)**，得到完整请求，照着写最省事。

## 四、第三步：用 Python 复刻

### 1. 从浏览器拿 Cookie

因为已经连上了登录的 Edge，可以直接把 Cookie 导出来：

```python
cookies = driver.get_cookies()
cookie_str = "; ".join(f"{c['name']}={c['value']}" for c in cookies)
```

### 2. 循环翻页拿数据

```python
import requests

headers = {
    "Cookie": cookie_str,
    "User-Agent": "把抓包里的 UA 复制到这里",
    "Referer": "https://tieba.baidu.com/",
}

for pn in range(1, 999):
    resp = requests.get(
        "把抓包里的接口 URL 复制到这里",
        params={"pn": pn, "rn": 30, "uid": "你的uid", "ie": "utf-8"},
        headers=headers,
        timeout=10,
    )
    data = resp.json()
    # 在这里解析 data，拿到每条回贴的 id
    # 如果这一页没有数据了，就 break
```

### 3. 解析 JSON

不同接口返回结构不一样，需要你自己在 Response 里看。一般思路：

- 列表数据通常在一个 `data` 字段里，是个数组；
- 每条回贴有个唯一 ID（常见字段名：`thread_id` / `tid` / `pid` / `reply_id`）；
- 翻页信息可能有 `has_more` / `has_next` 之类的标志。

## 五、第四步：抓到「删除」接口

1. 回到页面，**手动点一次删除**（别真删，或删一条测试帖）。
2. 同时盯着 Network，找那个新发的 **POST** 请求。
3. 分析它：
   - URL；
   - 表单参数（一般带贴子 id、回复 id）；
   - 是否有 `tbs`（贴吧的 CSRF token，通常每次请求都要带，一般在 Cookie 或页面里）。
4. 用 requests 复刻删除：

```python
resp = requests.post(
    "删除接口 URL",
    data={"tid": ..., "pid": ..., "tbs": ...},
    headers=headers,
)
```

## 六、风险提示

- 直接调接口比 UI 自动化**更容易触发频率限制 / 风控**，务必加 `time.sleep` 控制节奏，别连发。
- 部分贴吧接口带**签名参数（`sign`）**，是前端 JS 算出来的。如果抓到带 `sign` 的请求，复刻难度大很多，需要逆向 JS。遇到这种情况，UI 自动化反而是更省事的选择。
- 接口会变，抓一次不等于永久可用；失效了重新抓一遍即可。

## 七、建议的落地方式

- 先做「只读」版：只调分页接口，把回贴 ID 打印出来，验证翻页和 Cookie 都对。
- 再做「删除」版：对着打印出来的 ID 调删除接口，一次删一条，逐步放量。
- 跑通后，把接口版做成 `main.py` 的「快速模式」，保留现在的 UI 版作兜底。
